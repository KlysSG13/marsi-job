## 1. Аудит резюме — SKU `resume_audit`, 199 ₽

### 1.1. Продукт

Кандидат запускает аудит своего резюме/профиля → отчёт: **скор качества резюме 0–100**, разбор по измерениям с конкретными правками и оценкой «исправь → +N к скору матча».

### 1.2. Детерминированное ядро (новый модуль `resume_audit.py`, без LLM)

Измерения (веса и пороги — в конфиге, см. 1.5), каждое — чистая функция проверки по профилю и распарсенному резюме:

1. **Полнота профиля** — % заполненных факторов из анкеты (пустые секции = список «дозаполнить»).
2. **Подтверждённость (g)** — задекларированные скиллы без портфолио/ссылок/подтверждений; сколько факторов с низким g.
3. **Портфолио и публичные артефакты** — наличие GitHub/кейсов/ссылок.
4. **Опыт** — пробелы в датах > 6 мес без объяснения, общая длительность vs заявленный грейд.
5. **Заголовок и позиционирование** — название роли соответствует стеку/грейду; «универсальное» резюме без специализации — штраф.
6. **Формат и контакты** — длина резюме, структура разделов, зарплатные ожидания указаны/нет.
7. **Языки** — соответствие заявленного уровня типичным требованиям его топ-матчей (по его же топ-5 вакансий из `/match`).

Итог: взвешенная сумма → 0–100; каждое измерение — статус (ок / внимание / критично) + 1–3 конкретных действия.

### 1.3. LLM-часть (опционально)

Если `MARSIJOB_LLM_KEY` задан — секция «Формулировки»: 3–5 замечаний по тексту резюме (штампы, достижения без цифр, структура). Без ключа продукт полностью работоспособен, секция просто отсутствует. LLM только формирует текст замечаний по строгой схеме; все числа/скор — из детерминированной части.

### 1.4. Бесплатный крючок

**Мини-аудит один раз** (флаг `audit_teaser_used`): скор 0–100 + топ-1 проблема + «полный отчёт с правками — 199 ₽». Полный аудит — после оплаты (1 запуск = 1 отчёт; повторный прогон в течение 48 ч после правок профиля — бесплатно, тем же entitlement).

### 1.5. Конфиг

SKU в `pricing.json`: `{"id": "resume_audit", "audience": "candidate", "type": "service", "price_kop": 19900, "title": "Аудит резюме", "receipt_name": "Аудит резюме МАРСИ-Job"}` + блок `"resume_audit": {"rerun_window_hours": 48, "dimensions": {...веса...}}`.

## 2. Мок-интервью с ИИ — SKU `mock_interview` 299 ₽/сессия и `mock_interview_3` 799 ₽/3 сессии

### 2.1. Продукт

Собеседование в чате с ИИ, персонализированное по данным кандидата: 5–7 вопросов по его слабым факторам (из зоны валентности `/why`) и ключевым требованиям его топ-вакансии; в конце — отчёт с обратной связью.

### 2.2. Сценарий сессии

1. `/interview` (или из `/buy`) → если оплачено — выбор фокуса: «по моим слабым местам» / «по вакансии X» (его топ-3 матч-вакансии) → старт.
2. Вопросы приходят **по одному**; после ответа кандидата возможен **1 уточняющий** вопрос; затем следующий.
3. Лимиты: **7 вопросов**, 45 минут на сессию (`expires_at`), переписка вне ответов игнорируется; `/cancel` — завершить досрочно с укороченным отчётом (минимум 3 ответа).
4. **Финальный отчёт**: оценка по критериям (структура ответа STAR, конкретика/цифры, релевантность опыту, пробелы), 3 сильных и 3 слабых мест, 2 переписанных примера ответов (LLM), план подготовки на 30 минут/3 часа.

### 2.3. LLM-требования

- Генерация вопросов: system-prompt со строгим контрактом JSON (вопрос, цель, проверяемый фактор, критерий идеального ответа); вход — сводка профиля + пробелы валентности + требования вакансии. Транскрипт вопросов и «эталоны» не показывать кандидату до конца сессии.
- Оценка ответов: по завершении сессии — один запрос на отчёт по строгой схеме.
- Жёсткие капы на стоимость: `max_tokens` на генерацию вопроса и на отчёт в конфиге; при недоступности API — вежливая пауза сессии на 5 мин и ретрай, не списывать сессию при сбое до первого вопроса.
- **Без `MARSIJOB_LLM_KEY` SKU скрывается из `/buy`** (и `/interview` отвечает «продукт временно недоступен»). Кнопка не должна вести на оплату недоступного.

### 2.4. Приватность

Полный транскрипт переписки **не сохраняется** (только в памяти сессии); в БД — сводка: id, статус, вопросы_задано, скоры по критериям, created/expires. Удаление профиля удаляет и сводки сессий.

### 2.5. Конфиг и БД

SKU: `mock_interview` (service, 29900) и `mock_interview_3` (consumable, quantity 3, 79900; списание 1 за сессию). Блок `"mock_interview": {"questions_max": 7, "followups_per_question": 1, "session_ttl_min": 45, "min_answers_for_report": 3, "gen_max_tokens": ..., "report_max_tokens": ...}`.
Таблица `interview_sessions(id, tg_id, status active/finished/expired/cancelled, focus, vacancy_id NULL, questions_asked, summary_json NULL, created_at, expires_at)`.

## 3. Дорожная карта «+X очков» — SKU `roadmap`, 349 ₽

### 3.1. Продукт

План на 3 месяца: какие факторы поднять (в порядке убывания влияния на скор), что сделать по каждому, ожидаемый прирост. Строится **детерминированно из зоны валентности** (модуль `valence.py` — только чтение): для каждого кандидата движок уже умеет ранжировать «обнуление какого фактора максимально поднимет скор» — дорожная карта разворачивает это в план.

### 3.2. Сценарий

1. `/roadmap` → выбор цели: топ-3 его матч-вакансий («под эту вакансию») или «общий рост скора» (агрегат по его топ-10 матчам).
2. Бесплатный предпросмотр: топ-1 пробел + ожидаемый Δ (крючок). Полная карта — после оплаты (1 запуск = 1 отчёт, привязан к выбранной цели; сохраняется в профиле, пересчёт после правок профиля — 199 ₽... **нет**: пересчёт в течение 30 дней — бесплатно тем же entitlement, см. конфиг).
3. **Отчёт**: по месяцам (1/2/3) — 2–4 пункта вида «фактор → действие → где взять (курс/задача/правка профиля) → +Δ к скору»; итог «прогноз скора по цели: сейчас 0.62 → 0.78»; предупреждение о неопределённости (ε): план опирается на текущие данные вакансий.

### 3.3. Конфиг

SKU: `roadmap` (service, 34900). Блок `"roadmap": {"horizon_months": 3, "recalc_window_days": 30, "max_items_per_month": 4}`. Результат хранить в `purchases.payload` / отдельной таблице `roadmaps(tg_id, target_type, vacancy_id NULL, report_json, created_at)`.
